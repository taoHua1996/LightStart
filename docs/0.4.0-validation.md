# LightStart 0.4.0 validation

- Core policy checks: 71 assertions passed, including lower-corner geometry, invalid IDs and ambiguous labels.
- Android preference checks: 8 assertions passed. Automatic learning preserves manual rules and respects its toggle. Protection respects pause and its persistent stop preference.
- MuMu, Android 12 / API 32: a separate-package fixture with a real resource ID was clicked in the lower-right corner, and its ID was learned. Reusing that ID for a payment label produced no click. Restoring the skip label produced one accepted click.
- Foreground protection: notification and foreground-service state verified. Closing the activity and removing its actual recent task kept the service running; skipping still worked afterward.
- Two actual emulator reboots: opted-in protection restarted from BOOT_COMPLETED. After stopping protection from its notification, it remained off across reopening the app and a second reboot, even with boot restoration enabled. Original emulator preferences were restored after testing.
- UI: light/dark modes, enlarged text, landscape and a compact portrait viewport inspected. Runtime display overrides were restored.
- APK signature verification passed. Android Lint reported no errors; its two warnings concern the explicit battery-exemption request and the synchronous write used to persist a notification stop before terminating the service.

- Physical phone, Android 16 / API 36: version 0.4.0 (code 8) installed successfully. The previous installation was absent from the primary user profile at installation time, so there was no old app data to migrate. The accessibility service was bound, foreground protection and its notification were running, and all 158 configurable apps were enabled.
- On that phone, the built-in demo and Xiaocan produced accepted click events. These events confirm that Android accepted the actions; they do not independently prove visual ad dismissal. Automatic ID learning and boot restoration were enabled. OEM autostart permission and reboot recovery on the physical phone remain unverified.

Emulator success does not establish every OEM's autostart or cleanup behavior. Debug APKs signed with different keys cannot replace each other in place. Use the local-signed release asset to update the corresponding local installation; do not uninstall an existing installation without preserving any needed local data first.
