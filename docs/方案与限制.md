# 轻启：实现方案与系统边界

## 结论

不使用 Root 的可落地路线是 **AccessibilityService（无障碍服务）识别并点击开屏跳过控件**。它属于辅助跳过，不是跨应用广告防火墙。不能保证阻止所有广告、摇一摇、自动深链或误触后的跳转，也不能保证被清理、强停后永久运行。

## 权限与能力

| 权限或能力 | 本版处理 | 能做什么 / 限制 |
| --- | --- | --- |
| 无障碍服务 + 读取窗口控件 | 必需，系统设置手动授权 | 临时读取文字、资源 ID、位置，提交控件点击；自绘画面、部分 WebView 或未暴露节点的按钮不可识别 |
| BIND_ACCESSIBILITY_SERVICE | 声明在服务上 | 只允许系统绑定，并非普通运行时弹窗授权 |
| RECEIVE_BOOT_COMPLETED | 使用 | 记录收到开机通知的时间；不能借此自行启用或绑定无障碍 |
| 包可见性 queries | 查询可启动应用、桌面、拨号入口 | 不使用 QUERY_ALL_PACKAGES；其他用户、工作资料中的应用不保证可见 |
| 电池优化 | 引导用户进入系统设置 | 用户可手动选择不限制；豁免不能抵消强行停止或厂商策略 |
| 厂商自启动/后台锁定 | 提供通用引导 | 品牌和系统版本入口不同，不伪造“设置成功” |
| 悬浮窗、通知、VPN、使用情况访问 | 不申请 | 本方案不依赖这些权限 |
| 网络 | 不申请 | 所有检测和统计只在本机进行 |
| Root / Shizuku | 不使用 | 不修改系统，不注入第三方应用，不伪装常驻能力 |

Android 13 及以上部分侧载来源会触发“受限设置”；需要用户从应用详情允许受限设置，具体步骤由系统/厂商决定。应用不能绕过此限制。安卓新版本的后台启动与前台服务限制意味着增加常驻通知也不能保证永生；本版不滥用前台服务类型保活。

## 实际功能

1. **首次授权**：展示无障碍用途、读取范围、处理方式及限制，用户明确同意后再进入系统设置。即使直接在系统开启服务，未在轻启同意也不会执行点击。
2. **逐应用开启**：默认关闭所有第三方应用；过滤桌面、输入法、拨号、权限管理、安装器、系统设置和轻启自身。
3. **保守规则**：只匹配右上区域中完整的“跳过 / Skip / 跳过广告 / Skip ad”及倒计时形式，不进行包含“跳过”即点击的匹配。
4. **自定义规则**：可为每个应用设置完整文字和资源 ID；两者同时填写时要求同时匹配。自定义不再要求右上位置，但仍检查控件大小、包名、可见性及启用状态。
5. **扫描窗口**：仅当前台包变化后 12 秒内；同包窗口变化不延长时间。它是前台进入时间窗，不能可靠识别真正冷启动；回到前台也可能开启一轮。
6. **控制误操作**：只调用 ACTION_CLICK，不使用坐标手势；最多上溯两层可点击父节点；目标不超过当前窗口面积的 1/8；每轮最多尝试一次，拒绝也不循环点击；每次最多遍历 250 个节点，间隔约 350ms；锁屏或屏幕关闭不执行。
7. **统计**：只将 ACTION_CLICK 返回 true 的第三方操作计入累计与每日统计。true 表示系统接受操作，不证明广告已消失或跳转已阻止。记录保留最多 500 条，界面显示最近 100 条；每日/累计聚合不依赖明细保留数量。每日按执行时的本地日期归档，改变时区不会重写历史。
8. **演示**：内部模拟开屏页具有真实跳过按钮，不自动倒计时关闭。只有服务点击会留下演示记录，不计入第三方统计；手动点击也会移除模拟页，但不会产生服务日志。
9. **状态**：区分未授权、已授权等待系统连接、已连接、已暂停；回到概览会刷新。服务连接不代表某个第三方应用一定有可匹配控件。

## 不能承诺的功能

- 不能全面阻止其他 APP 的广告请求或深链。VPN/DNS 只能挡一部分独立广告域名，同域广告可能误伤业务，也不能改变 UI 或可靠禁止 Intent 跳转；不作为首版核心路线。
- 不能拦截系统分发给别的应用的加速度传感器事件，因而不能彻底禁用摇一摇广告。
- 不使用“跳转后自动按返回”的通用策略：这既非真正阻止跳转，也容易打断支付、登录或用户主动导航。
- 不能自动打开无障碍权限、突破强停、自动点击系统权限弹窗。
- 从最近任务中划掉不等于强停，但厂商可能连同服务清理；重启是否恢复取决于系统和授权状态。
- 默认规则不适配每款 APP；特定包名/版本/按钮信息仍需在目标手机验证，自绘控件可能无法支持。
- Google Play 对无障碍 API 使用、披露及用途有审核要求。本版不标记为为残障人士提供核心辅助功能的工具（isAccessibilityTool=false）。生成 APK 不等于获得上架许可。

## 架构

```text
MainActivity：概览 / 应用列表 / 规则 / 统计 / 权限引导
       ↓                      ↓
SharedPreferences         SQLite Store
       ↓                      ↑
AccessibilityService → SkipPolicy → ACTION_CLICK 结果
       ↑
Android 系统绑定与恢复（应用不能替代）

BootReceiver：仅记录开机通知，不启动前台服务
DemoActivity：可手动验证的模拟开屏
```

## 分期

- 当前 0.3：工程、授权、基础规则、逐应用与批量开关、自定义规则、SQLite 统计、演示、后台引导、调试 APK，以及开源仓库和每次推送自动打包。
- 手机验证：根据目标手机测试冷启动/热启动、后台清理、重启、受限设置与具体广告按钮；记录不兼容原因。
- 后续增强：基于真实应用版本维护规则包；增加仅在特定页面特征出现时匹配的约束，降低热启动误触；经验证后再评估本地规则导入导出。
- 发布：确定应用身份和签名密钥、完成设备矩阵和隐私说明，按分发渠道要求处理无障碍声明。
