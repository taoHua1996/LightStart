# LightStart 0.3.2

## Changes

- Keep the test button visible on Overview, including before setup is complete. Missing permissions, a disconnected service, or a paused master switch now produce an actionable explanation. The demo does not require enabled third-party apps.
- Show the latest local check result: app disabled, no matching clickable button, click accepted, or click rejected. Only the app label and a fixed status message are stored; screen text is not retained.
- Establish foreground sessions from the actual window root when scanning. A state event arriving before a usable root no longer permanently loses that foreground session. Window-change events and bounded transition retries help recover from stale or missing roots.
- Recognize exact `跳过广告` and `Skip ad` labels, including countdown variants. Existing geometry, app opt-in, one-attempt, and 12-second limits remain in place.

## Validation

- 57 JVM policy assertions passed, including delayed foreground observation, missing roots, unchanged deadlines, duplicate-click prevention, and precise ad-label matching.
- Debug APK build, Android Lint, and APK signature verification passed.
- MuMu Android 12: upgrade installation, the fixed test entry, the pause/recovery explanation, and automatic demo clicking passed.
- Separate test APK: disabled-app diagnostics worked; a delayed `跳过广告` button was clicked automatically after enabling that test app, with one accepted event recorded.
- Existing application settings and statistics were preserved. Device validation did not run the destructive database instrumentation suite.

These results do not establish the cause of the reported phone failure or confirm compatibility with all real advertisements. The phone still needs the updated APK and an Overview/test result to distinguish setup, service, and matching failures.
