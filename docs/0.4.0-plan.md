# LightStart 0.4.0

## Automatic resource IDs

Match exact skip labels in the upper-right or lower corners during the existing 12-second launch window. Keep package, visibility, enabled-state, bounds and area checks. After Android accepts the click, store a valid resource ID under the target package. Use it for faster subsequent lookup while rechecking the current label and geometry. Preserve manual rules and fall back to text when no ID is available. This does not perform OCR or guess coordinates for inaccessible views.

## Startup and background protection

Add a Settings tab with independent controls for automatic ID learning, foreground protection and restoration after boot. Protection uses a user-visible notification, a persistent stop action and a sticky service. It runs only with consent, the main skip toggle and accessibility authorization. Notification permission, battery exemption, app information and OEM autostart settings have explicit entry points. Unavailable OEM entry points fall back to an explained app-information action.

Boot restoration is opt-in and applies to the protection service. Android owns accessibility binding. Closing the activity leaves protection running, but force-stop, the Android task manager, permission removal and OEM cleanup can still terminate it. There is no claim of an unkillable process or silently granted system permissions.

## Validation

Run core matching regressions, Android Lint, APK signature verification and emulator integration checks for learning, manual-rule preservation, bottom-corner detection, protection startup/stop and activity dismissal. Keep real-phone results separate and preserve existing data when upgrading. Debug builds require a matching signing certificate for an in-place update. See [validation results](0.4.0-validation.md) for completed checks and remaining device-specific limits.
